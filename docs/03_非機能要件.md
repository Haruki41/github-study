# 非機能要件

[← 要件定義書に戻る](../要件定義書.md)

機能以外の品質や条件（使いやすさ・速さ・安全性など）です。

| 区分 | 内容 |
|---|---|
| 動作環境 | 利用者本人のPC（localhost）で動かす。Docker Desktop、Java 17、Node.js が必要。DB・API・画面の3つを起動して使う（[07_技術要件](./07_技術要件.md)） |
| 使いやすさ | 初めて使う人が説明なしで、追加・移動・削除・検索を操作できる |
| 性能 | 数十枚のカードで操作に遅延を感じない。画面の表示に必要なデータは、1回の API 通信で取得する |
| 保存 | データは PostgreSQL（Docker のボリューム `pgdata`）に保存する。通信はPC内（localhost）だけで、外部へ送信しない。コンテナを停止してもデータは残るが、ボリュームを削除すると消える |
| データ整合性 | 外部キーの `ON DELETE CASCADE` により、列を削除するとその列のカードも DB が自動で削除する |
| 安全性 | 入力文字は HTML として解釈させない（React の自動エスケープを使い、`dangerouslySetInnerHTML` は使わない）。SQL は `?` のパラメータで渡し、文字列連結で作らない。DB は自分のPCからのみ接続でき、DB のパスワードは学習用のローカル専用の値を使う |
| 障害時の表示 | API に接続できないときは、画面にエラーを表示し、画面が真っ白にならないようにする |
| 保守性 | フロントエンド（`frontend/`）とバックエンド（`backend/`）を分ける。バックエンドは Controller → Repository → DB の3層にする。変更は Issue → ブランチ → PR の手順で行う |
