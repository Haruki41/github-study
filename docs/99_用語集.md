# 用語集

[← 要件定義書に戻る](../要件定義書.md)

| 用語 | 意味 |
|---|---|
| スコープ | プロジェクトで「どこまでやるか・やらないか」の範囲 |
| 要件定義書 | 作るものに求められる内容を整理した文書 |
| 機能要件 | アプリに備えてほしい機能（追加・移動・削除など） |
| 非機能要件 | 機能以外の条件（使いやすさ、速さ、安全性など） |
| 受け入れ基準 | 完成と認めるための確認条件 |
| 優先度 | 必須＝今回必ず作る／任意＝余裕があれば作る |
| ユースケース | 利用者がアプリを使ってやりたいこと（例：タスクを追加する） |
| 操作フロー | ユースケースを実現する操作の手順と流れ |
| カード | 1件のタスクを表す四角い表示 |
| 列 | カードを置く縦の区分（未着手・進行中・完了） |
| ドラッグ＆ドロップ | マウスでカードを掴んで（ドラッグ）、別の場所で離す（ドロップ）操作 |
| ER図 | データの種類（テーブル）と、それらの関係を表す図 |
| テーブル | データベースの中で、表の形でデータをしまう入れ物 |
| 主キー（PK） | 行を一意に区別する項目 |
| 外部キー（FK） | 他のテーブルの行を指し示す項目。テーブル同士をつなぐ |
| IndexedDB | ブラウザに最初から備わっているデータベース。旧版の `index.html` で使っていた。別のブラウザや別のPCには引き継がれず、ブラウザのデータ削除で消える |
| オブジェクトストア | IndexedDB でのテーブルの呼び名（旧版で使用） |
| フロントエンド | 利用者が見て操作する画面側のプログラム（React） |
| バックエンド | 画面からの依頼を受けて、データベースを読み書きする裏側のプログラム（Spring Boot） |
| API | プログラム同士が通信するための窓口。画面はバックエンドの API を呼んで、データを取得・更新する |
| PostgreSQL | 本格的なデータベースソフト。Docker のコンテナとして動かす |
| Docker / コンテナ | アプリを、PCを汚さず隔離した環境で動かす仕組み。`docker compose up -d` で DB を起動する |
| React / Vite | 画面を作るためのライブラリ（React）と、その開発サーバー・ビルド道具（Vite） |
| プロキシ | 通信の中継。画面の開発サーバーが、`/api` への通信をバックエンドへ転送する |
| CORS | 別の場所（ポート）のサーバーへの通信を、ブラウザが制限する仕組み。プロキシを使うことで問題にならない |
| Issue / PR | 作業の内容を記録する GitHub の仕組み（Issue）／変更を `main` に取り込むための依頼（Pull Request） |
| 非同期処理 | 結果を待たずに次の処理へ進み、結果が出たら続きを実行する方式。`Promise` や `async/await` で書く |
| JSON | データを文字で表す形式。保存や読み込みに使う |
| textContent / エスケープ | 入力された文字を、HTMLの命令ではなく単なる文字として表示する方法。悪意ある入力から守るために使う。旧版は `textContent`、React は標準で自動エスケープする |
| HTML / CSS / JavaScript | 画面の骨組み／見た目／動きを作る3つの言語 |
| Drag and Drop API | ブラウザに最初から備わっている、ドラッグ＆ドロップ用の機能 |
| ID | 一つ一つを区別するための番号 |
| Spring Boot | Java で API サーバーを作るための枠組み（フレームワーク）。バックエンドで使っている |
| Gradle | Java のプログラムをビルド（組み立て・実行）する道具。`./gradlew` で動かす |
| TypeScript | JavaScript に「型」を加えた言語。間違いを書いた時点で見つけやすい。フロントエンドで使っている |
| Oxlint | コードの書き方の問題を、実行前に調べる道具（`npm run lint`） |
| ブランチ | 変更を、本線（`main`）から分けて進めるための作業用の枝。名前は `feature/12-xxx` のように決める |
| マージ / Squash and merge | PR の変更を `main` に取り込むこと。Squash は、PR の複数のコミットを1つにまとめて取り込む方式 |
| hooks（フック） | Claude Code が操作を実行する前後に、自動で動く検査。`main` への直接 push や、決められた以外のポートでの起動を止める |
| スキル | Claude Code に、決まった手順を覚えさせる仕組み。`dev-servers` は、サーバーを決められたポートで起動・停止する手順 |
| ホットリロード（HMR） | コードを保存すると、ブラウザの画面が自動で更新される開発用の機能。Vite の開発サーバーが持つ |
| トレーサビリティ | 要件が、設計・実装・テストのどこにつながっているかを追跡できること。機能ID（F-01 など）で各ドキュメントを紐づける |
